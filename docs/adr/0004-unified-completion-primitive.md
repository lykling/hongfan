# ADR-0004：统一补全原语 complete()

- **状态**：已接受
- **日期**：2026-09-08
- **决策者**：Pride Leong
- **关联**：[00-design.md](../00-design.md) §2.3、§3.4、D4

## 背景

正向推衍也是多解的：规则带概率、候选冲突、粒度自由度时，一个起点张开整棵可能未来之树。v0.1 曾把正向的逐步裁决（DecisionPolicy）与逆向的整体择优（SolutionPolicy）拆成两个接口——这是伪分割：两者都是在"合法轨迹集合"上做选择，差别只在边界条件（固定哪些切面）与选取时机（在线逐步/离线整体）。

## 决策

**一个原语**：

```
complete(R, B, P, bounds) → 轨迹（或多条轨迹 / 松弛报告）
```

切面集 B 的形态决定操作的面貌：仅起点=正向推衍；起点+目标=规划；两端或多锚点=界间还原（布朗桥）；仅终点=溯因；单事实=explain 溯源；零切面=创世。策略接口合一（在线/离线两种咨询模式，ADR 见 [0016](0016-llm-boundary.md) 无关，见 00-design §11）。

## 后果

- 接口需同时容纳在线/离线两种咨询；实现层仍分两执行器（皇极在线 / 稽疑离线）
- explain、平行世界、矛盾松弛等能力都从同一原语自然生长，无需新入口
- M1 落地：在线补全（derive）+ 前向枚举式界间补全（complete，枚举即正向执行即验证）
