# ADR-0019：求解器层——提案与验证分离

- **状态**：已接受
- **日期**：2026-09-11
- **决策者**：Pride Leong
- **关联**：[00-design.md](../00-design.md) §7.5、§7.8、[0016](./0016-llm-boundary.md)

## 背景

"怎么搜"与"选哪个解"是正交问题。强力算法（启发式搜索、数值优化、采样滤波）若进入核心内核，确定性契约（Run 可复现 / 轨迹可验证 / 不变量必守）将被侵蚀；若以规则表达算法，又混淆了"世界的物理"与"解世界的方法"。

## 决策

- **三层正交**：规则（问题定义）/ 求解器（怎么搜）/ 策略（选哪个解）
- 求解器接口：`propose(规则视图, 切面集, 界限) → 候选轨迹集`——可插拔纯函数
- **统一边界：求解器只提案，经典内核验证**——出口统一正向重放；一切求智者（数值求解器 / 启发式 / 大模型）同等待遇。[0016](./0016-llm-boundary.md) 是本原则在 LLM 上的特例，本 ADR 将其推广到全部强力算法
- **代价模型扩展**：步代价 → 转移代价与轨迹泛函（Σ / max / 平滑项）；MinCost 即轨迹优化，Preference 即软约束（拉格朗日视角）

## 后果

- 求解器生态可无限丰富而不破坏核心承诺；内核保持"慢而正确"
- 平滑可表达为轨迹修正规则包（规则匹配轨迹模式）或代价泛函——不必发明新机制
- 每个新求解器的验收标准固定：产出候选能通过正向重放，且同一输入下确定
